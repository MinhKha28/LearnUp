# UC27.2 backend — D85–D91

Base: origin/develop `0ce07c0`. Backend only; Course completion and completion events are deferred by D89.

## Configuration and responses

`VIDEO_PLAYBACK_MODE` is required: `course` returns 503 `PLAYBACK_UNAVAILABLE` after access/content checks; `fixture` requires an HTTP(S) `VIDEO_FIXTURE_URL` and refuses startup in production.

GET `/api/v1/enrollments/:enrollmentId/materials/:materialId/playback` reads title/disabled flags from I2, duration from the existing snapshot, and never writes. A missing snapshot returns `MATERIAL_NOT_FOUND`.

POST at the same path ending in `/progress` accepts `{ranges:[[start,end],...],positionSeconds:10,reportedAt:"2026-10-22T06:00:00.000Z"}`. Ranges contain 0–20 finite numeric pairs; an empty list reports position only. Position must be a nonnegative integer. reportedAt is an ISO timestamp with a time zone. Invalid input keeps the existing 422 VALIDATION_ERROR contract; no new error code is introduced.

GET and POST return positionSeconds and positionReportedAt (both null for legacy rows without a bookmark), plus the existing coverage/completion fields. GET playback also returns the authenticated learnerId for the per-user session cache; POST excludes title/playbackUrl. maxPlaybackRate is removed. The fixture/course playback mode contract remains unchanged; signed URLs (L10) are deferred.

BR-182 stores position separately from watched_ranges. Position is clamped to snapshot duration and updated only when position_reported_at is null or older than reportedAt. Client times more than 60 seconds ahead use server time. Position updates do not modify completion or coverage timestamps. Reports lock the owned Enrollment and progress row, then save coverage and position in one transaction. Existing snapshot FK/organization scoping remains intact.

BR-184: Enrollment Completed accepts a bookmark but ignores ranges, preserving watched_ranges, completed_at and last_reported_at. Completed material in an unfinished Enrollment may accumulate additional coverage while completion stays permanent. BR-140 activates NotStarted only on the request that first completes a material. BR-181 keeps inward whole-second normalization and PostgreSQL multirange union, without a playback speed budget or PROGRESS_RATE_EXCEEDED.

Migration: `20261022000000_video_resume_position` adds nullable integer position_seconds and timestamptz position_reported_at, with a nonnegative-position constraint. No backfill infers bookmarks from coverage. Existing migrations remain unchanged.

## Reproduce

1. Apply learning migrations and generate Prisma client; build learning-service. Configure existing DB/internal-key/course/tenant/assessment environment and `VIDEO_PLAYBACK_MODE=course`.
2. Build the existing learning-service Dockerfile and run it in `learnup_learnup-network` with network alias `learning-service`, port 8085, and its existing internal key/database configuration. Use PostgreSQL container DNS in DATABASE_URL. Do not start a native host process for the measured API.
3. From repository root run `pwsh -File perf/learning/uc27.2-run.ps1`. It seeds, explains, resets each level, runs grafana/k6, verifies database counts, and cleans fixtures in finally. It reads the local internal key without printing it. Raw output stays in gitignored `perf/learning/results/`.
4. Stop the measurement service after the run. The fixture helper also supports explicit `cleanup` for an interrupted process.
